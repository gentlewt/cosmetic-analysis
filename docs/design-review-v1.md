# 설계서 v1.0 대조 및 이번 단계의 범위

기준: 사용자가 첨부한 「내 화장품 조합, 나에게 잘 맞을까? – 데이터베이스 설계서 v1.0」, 설계 기준일 2026-11-09. DOCX 본문을 직접 읽어 대조했다. ChatGPT 프로젝트의 다른 문서나 기존 Supabase 실제 스키마에는 접근하지 않았다. 문서의 권장 DB 생성 순서는 이번 요청의 DB 무변경 범위를 확장하는 지시로 취급하지 않았다.

## 화면과 루틴: 차이 및 조치

| 항목 | 이전 시제품 | 이번 단계 |
| --- | --- | --- |
| 홈 | 홍보·예시 제품 중심 | 마지막 확정 아침·저녁 루틴 중심 |
| 시간대·빈도 | 단일 선택 집합 | 아침·저녁 독립 목록, 매일/격일/주 2~3회/주 1회/필요할 때 |
| 순서 | 없음 | 드래그(마우스·터치), 위·아래 버튼(키보드), 제거·추가 |
| 확정 | 선택 즉시 메모리 변경 | 초안과 확정 분리, ‘이대로 루틴 확정하기’로 두 루틴 일괄 저장 |
| 버전 | 없음 | 확정할 때 새 브라우저 버전, 이전 버전 연결·확정 시각·제품 버전 ID 보존 |
| 비교 | 최대 2개 | 최대 4개, 5개 가상 제품으로 제한 동작 검증 |
| 관심제품 | 없음 | 별도 저장·해제·개인 메모, 루틴과 독립 |
| 제품 사진 | 임의 병 그림 | 사진 없으면 회색 배경 ‘이미지 준비중’ |
| 제품 상태 | 없음 | 미승인 예시에만 ‘임시 등록 · 검증 필요’ |
| 분석·추천 | 예시 성분 중복·일반 관리 설명 | 분석 결과 제거, 승인 정보·분석 기준 연결 전 준비 중 표시 |
| 성분 상세 | 출처 없는 설명 | 성분명만 제공, 승인·근거 연결 전 설명 보류 |
| 피부 변화 상태 | 편안함/건조함 등 | 좋아짐/비슷함/나빠짐 및 관련 고민, 기존 브라우저 기록 유지 |
| 비회원 루틴 | 새로고침 시 소실 | 확정 루틴·관심제품 브라우저 저장, 마지막 사용 30일 만료 확인 |

루틴 초안은 탭 내 메모리에 유지된다. 다른 메뉴에서는 확정 루틴만 보이며, 확정하지 않고 새로고침/탭 닫기 시 브라우저 경고 후 초안이 사라진다. 취소는 두 시간대 초안을 마지막 확정 상태로 되돌린다. 빈 루틴도 기존 확정 상태에서 항목을 모두 제거한 뒤 확정할 수 있다. 동일 시간대의 같은 제품 중복은 이번 UI에서 방지한다. 순서는 배열 위치(화면 번호 1부터)로 보존하며 DB의 순서 필드 매핑은 후속 작업이다.

## 미구현 및 후속 작업 (DB 작업 없이 완료했다고 주장하지 않음)

| 설계 영역 | 남은 차이 |
| --- | --- |
| 회원·인증, 피부 설문 | Supabase Auth, PIN 보안 검토, 프로필/설문 및 버전 보존 미연결 |
| 제품·성분·연구 | 실제 제품/전성분 버전, 별칭·기능·주의·연구 조건·출처 및 승인 워크플로 미연결 |
| 루틴·분석 | 서버 버전 저장·회원 접근 통제·분석 스냅샷·실제 제품 버전 무결성 미검증 |
| 관심제품·피부 기록 | 서버 동기화·비공개 사진·권한 확인 URL·실파일 삭제 미연결 |
| 이용자 서비스 | 리뷰·신고·요청·문의・서비스 내 알림 미구현 |
| 관리자·운영 | 관리자 권한・감사 로그・약관・통계・AI 처리/비용 미구현 |
| 권한·파일·탈퇴 | RLS·Storage 정책·완전 삭제 작업 및 권한 테스트 미실행 |
| 비회원 이전 | 로그인 동의 후 서버 측 회원 ID 확인・병합 미구현 |

기존 `skin-diary` 로컬 기록은 보존한다. 예전 피부 상태 값은 소급 변환하지 않고 과거 기록에 그대로 표시한다. 피부 기록 전체의 만료·보존 정책은 미확정이므로 이번 루틴/관심제품 30일 만료에 함께 삭제하지 않는다. 만료 처리는 서버 예약 작업이 아니라 다음 브라우저 방문 시 수행한다. 브라우저가 닫힌 동안 자동 실행하지 못한다.

## 불명확하여 확정하지 않은 사항

- ‘확인된 주요 병용 주의 정보가 없는 경우’의 **기존 확정 안내 문구**는 첨부 문서에 없다. 임의 대체하지 않고 관련 분석 영역을 준비 중으로 둔다.
- 분석·추천 기준, 성분·연구 승인 데이터와 공개 정책의 구체값은 없다. 안전 점수·추천 순위·효능 등급을 만들지 않는다.
- 동일 시간대 같은 제품의 복수 단계 허용 여부, 저장된 루틴 버전의 복원 UI, 임시 제품 공개 범위는 추가 확정이 필요하다. 현재의 중복 방지는 UI 한정이며 DB 제약을 신설하지 않는다.
- 기존 Supabase 테이블·관계·정책과 설계서의 차이는 실제 스키마를 확인하지 않아 미검증이다.
- 브라우저의 예시 버전 이력은 서버 감사/불변성 보장이 아니다. 사용자나 브라우저 도구가 변경할 수 있다.

## 변경 금지 및 검증 경계

Supabase SDK 호출, SQL, 마이그레이션, 테이블/버킷 삭제·생성·재생성, 키 입력 및 Cloudflare 배포를 수행하지 않는다. 가상 데이터의 `*-demo-v1`은 실제 DB ID가 아니다. 실제 연결 시 기존 스키마와 정책을 먼저 읽기 전용으로 점검해야 한다.
