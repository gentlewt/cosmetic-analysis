# 내 화장품 조합, 나에게 잘 맞을까?

흰색·라벤더 테마의 반응형 스킨케어 웹서비스 초기 프로젝트입니다. Vite + JavaScript + CSS로 구성하며 Node.js 22.12 이상을 사용합니다.

## 개발

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

## 이번 단계 구현

- 홈: 마지막 확정 아침·저녁 루틴 표시
- 루틴: 시간대별 제품 추가·제거·드래그/버튼 정렬 및 다섯 가지 사용 빈도
- 초안과 확정 분리: **이대로 루틴 확정하기**로 두 시간대를 일괄 저장하고 새 버전 생성
- 확정 이력: 이전 버전·예시 제품 버전 ID·확정 시각 보존, 조회 제공
- 제품 비교 최대 4개, 관심제품 및 개인 메모는 루틴과 독립 관리
- 사진이 없으면 회색 ‘이미지 준비중’, 미승인 예시에만 ‘임시 등록 · 검증 필요’
- 확정되지 않은 분석·추천 및 출처 없는 성분 설명은 미제공

실제 데이터베이스 연동을 완료한 기능이 아니라 **가상 데이터와 브라우저 저장을 이용한 화면 구현**입니다. 상세 차이, 남은 작업, 불명확한 사항은 [설계서 대조 문서](docs/design-review-v1.md)를 확인하세요.

확정 루틴·관심제품은 localStorage의 `cosmetic-guest-v1`에 저장됩니다. 마지막 사용일 이후 30일이 지나면 다음 방문 시 삭제합니다. 브라우저를 변경하거나 저장 공간을 지우면 사라집니다. 편집 초안은 탭 메모리에만 유지되어 새로고침하면 사라지고, 메뉴를 이동해도 확정하기 전에는 홈에 반영되지 않습니다. 비교 목록은 탭 메모리에서만 유지됩니다. 로그인·회원 계정 이전은 미구현입니다.

피부 변화 기록은 기존 `skin-diary` 저장소를 유지합니다. 새 기록의 상태는 좋아짐/비슷함/나빠짐이며 이전 시제품의 기록은 변환·삭제하지 않습니다. 사진 업로드는 미구현입니다.

## Supabase (다음 단계)

현재 Supabase SDK, 네트워크 연결, 마이그레이션 및 초기화 명령은 없습니다. 기존 데이터베이스를 변경하지 않습니다. 필요할 때 `.env.example`을 `.env.local`로 복사하고 URL 및 브라우저용 publishable key를 설정하세요. VITE_ 변수는 빌드 결과에 공개되므로 service_role 키, 비밀번호, 서버 전용 API 키를 절대 입력하지 마세요. `.env` 및 `.env.*`는 예시 파일을 제외하고 Git에서 무시됩니다.

## Cloudflare Pages 설정 안내 (배포하지 않음)

- 프레임워크: Vite
- 빌드 명령: `npm run build`
- 출력 디렉터리: `dist`
- 프로젝트 루트: 저장소 루트
- Node.js: 22.12 이상

정적 파일만 출력하며 해시 라우팅이므로 별도 서버나 경로 리라이트가 필요하지 않습니다. 이 작업은 배포나 Pages 프로젝트 생성을 수행하지 않습니다.

## 테스트

- `npm test`: 검색, 시간대별 독립성, 정렬, 버전 스냅샷 불변성, 브라우저 저장/만료, 실패 처리, 4개 비교 제한 테스트
- `npm run build`: Cloudflare Pages용 정적 빌드
- `npm run test:browser`: Playwright로 PC/모바일 7개 화면, 마우스·터치 정렬, 일괄 저장·재조회·취소, 관심제품 독립성, 비교 제한, 저장 실패, 피부 기록 등을 검증. 자체적으로 임시 Vite 서버(4175)를 시작하고 종료합니다.

브라우저 테스트는 기본 `/usr/bin/chromium`을 사용합니다. 다른 설치 경로라면 `CHROMIUM_PATH=/path/to/chromium npm run test:browser`를 사용하세요. Chromium을 설치할 때 TLS 검증이나 네트워크 정책을 우회하지 마세요. 외부 폰트가 차단되면 시스템 글꼴을 사용합니다.
